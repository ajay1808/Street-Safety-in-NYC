# v1 — Motor Vehicle Safety in Manhattan (August 2022)

> **Archived as written.** This is the original 2022 notebook, preserved without
> corrections. Its reported metrics are not trustworthy — see
> [Known issues](#known-issues). For why it is kept this way and what replaces it,
> see the [top-level README](../README.md).

## What it does

A single Colab notebook, run top to bottom:

1. **Load boundaries** — Manhattan polygon from the NYC borough boundaries GeoJSON.
2. **Load crashes** — the 30,000 most recent citywide collisions from the NYC
   OpenData Socrata API; 5,399 fall within Manhattan.
3. **Build the street network** — `osmnx.graph_from_polygon(..., network_type='drive')`,
   then extract edges as a GeoDataFrame with `highway`, `maxspeed`, `oneway`, `length`.
4. **Snap crashes to edges** — `osmnx.distance.nearest_edges` maps each crash's
   lat/lon to an OSM edge, identified by the `(u, v, key)` triple.
5. **Build the panel** — the cartesian product of every edge × 12 months × 24 hours ×
   7 weekdays (~19M rows), sampled down and merged with the crash table. A row's
   target is 1 if a crash occurred on that edge in that time slot.
6. **Feature engineering** — parse `maxspeed` strings to numbers, one-hot encode
   month/hour/weekday/`oneway`, multi-label binarize `highway` class, standard-scale.
7. **Model** — `sklearn.svm.SVC(C=1.5, kernel='rbf')` on an 85/15 split.
   A `LinearRegression` variant is present but commented out.
8. **Score tomorrow** — build every edge × hour combination for the next calendar day,
   run it through the model, derive a per-hour Safety Score and Star Rating.
9. **Map it** — render the scored network.

**These numbers do not describe real-world performance.** They are measured on a
resampled distribution with a 35% crash rate; the true rate is about 0.03%. See below.

## Known issues

Listed in rough order of severity. Cell numbers refer to the notebook's execution
order.

### 1. Case-control sampling, never corrected (critical)

The panel is ~19M rows against 5,399 Manhattan crashes. Cell 37 keeps every crash but
samples only ~10,000 non-crash rows, producing a training set of 15,395 rows with
5,399 positives — a **35% crash rate against a true rate near 0.03%**, roughly a
1,000× oversample. No class weights (`class_weight=None`) and no prior correction are
applied, so the fitted model's scores are off by about three orders of magnitude in
absolute terms.

### 2. Accuracy reported at a 0.03% base rate

At the true base rate, a model that predicts "no crash" everywhere scores 99.97%
accuracy. Accuracy, and the precision/recall figures above, only describe the
resampled distribution — they say nothing about performance on real streets.

### 3. The displayed "probability" is not one

`SVC` is constructed with `probability=False`, so `.predict()` returns hard class
labels, not probabilities. The commented-out `LinearRegression` alternative would
regress a 0/1 target and produce unbounded values. The downstream map nonetheless
presents values such as `Accident probability: 0.899` and derives a Safety Score and
Star Rating from them.

### 4. Imputation leak on `maxspeed`

Cell 47 fills missing `maxspeed` with `'25 mph'`. Cell 49 then drops `highway`,
`oneway`, and `length` and re-merges them cleanly from the edge table — but
**`maxspeed` is not re-derived**. Crash-side rows entered the join without road
attributes, so they disproportionately carry the imputed default, giving the model a
partial shortcut to separate the classes.

### 5. Outer merge silently defeats the sample

Cell 37's `edges.merge(df_cal2, on=['uvkey'], how='outer')` re-introduces every edge
that was *not* sampled, with null time fields — 13,608 rows rather than the intended
10,000. Cell 49's `notna()` filter drops them later without comment.

### 6. `uvkey` assigned the wrong value

Cell 28 ends with `crashes_manhattan['uvkey'] = key`, storing the integer OSM key
instead of the `"u v key"` composite string built immediately above it. The
downstream merge joins on `u`, `v`, and `key` separately, so results are unaffected —
but the column is wrong and would break anything that relied on it.

### 7. Not reproducible

- `df_cal.sample(10000)` has no `random_state`
- `SVC(random_state=None)`
- `pip install matplotlib==3.1.3` — pinned to a 2020 release
- Hardcoded Colab paths (`/content/Borough Boundaries.geojson`)
- `warnings.filterwarnings('ignore')` at the top, masking the pandas
  chained-assignment warnings generated by the `for i in range(len(df))` loops

### 8. Random split on temporally structured data

`train_test_split(..., test_size=0.15, random_state=23)` splits the edge×time panel
at random. A model intended to predict an upcoming day should be validated on
held-out *future* time. The crash pull is also a single thin window — the 30,000 most
recent citywide records — rather than a multi-year history.

## Running it

The notebook was written for Google Colab and expects `Borough Boundaries.geojson` at
`/content/`. To run locally, change that path to point at the copy in this folder.

Crash data is fetched live from the Socrata API, so re-running will pull a different
30,000 records than the stored outputs and produce different numbers.

```
pip install osmnx pandas geopandas numpy matplotlib scikit-learn
jupyter notebook Motor_Vehicle_Safety_in_Manhattan_Project.ipynb
```

The `matplotlib==3.1.3` pin in cell 6 should be skipped on any modern environment.
